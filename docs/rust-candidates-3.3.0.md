## Что уже работает на Rust

Обновление 24.10.2026: также перенесён числовой цикл выбора очереди «Волны» (`native/compute-core/src/ranking.rs`). Добавлен опциональный экспорт `rank_wave` поверх ABI 2, пакетный адаптер и резервный JS-путь. Выполнены измерения полного формирования очереди с подготовкой и обменом данными: [отчёт с методикой и результатами](rust-wave-ranking-2026-10-24.md). Раздел о первом подключении удаления дублей ниже описывает предыдущий этап; отсутствие замеров и пересборки в нём относится к тому этапу.

`native/compute-core/src/lib.rs` реализует сравнение записей, семей песен и опечаток. Модуль вызывается через `src/shared/compute/waveSongMatrix.ts` из `sequenceWaveTracks` (`src/shared/utils/waveQueue.ts`). Обмен пакетный, ABI 2; размер входа ограничен 2 МиБ, память WASM — 16 МиБ, кандидаты — 1000, история — 300, показанные треки — 80. Для небольших задач и при недоступном WASM остаётся JavaScript. Порог включения — 5000 расчётных сравнений; это эвристика текущего кода, не результат новых замеров.

Исходный список ниже составлен по статическому обзору. После отдельного запроса пользователя внедрён приоритет 1: подключение существующего Rust/WASM-сравнения к удалению дублей в каталогах и жанрах. Изменён вызывающий код TypeScript; ядро Rust и ABI 2 уже содержат нужный алгоритм, поэтому дополнительного Rust-модуля и нового WASM-бинарника не понадобилось. Ускорение и снижение памяти пока не измерялись.

## Внедрение приоритета 1

- Общий `createSongDeduplicator` добавлен в `src/shared/compute/waveSongMatrix.ts`. Он вызывает существующую Rust-матрицу и предоставляет проверку дубля и отдельное подтверждение принятого кандидата.
- Подключены `cleanDiscoveryTracks` (`src/shared/utils/discoveryTracks.ts`) и объединение результатов `loadGenreCatalog` (`src/shared/services/genreCatalog.ts`). Это охватывает использующие общий отбор чарты, поиск песен для жанров и результаты SoundCloud.
- Матрица включается после 5000 фактически выполненных JS-сравнений, если оценка оставшейся работы также не меньше 5000 и в пакете не больше 1000 кандидатов. Это консервативная эвристика, не доказанный бенчмарком оптимум. Короткий результат большого входного списка не заставляет заранее считать полную матрицу.
- Совпадение проверяется в прежнем порядке: принятый трек → новый кандидат. Rust-матрица направленная; переставлять аргументы нельзя.
- В жанрах кандидат запоминается только после проверки лимита шести треков на исполнителя. Отклонённый кандидат не подавляет более поздние песни. Приоритет площадок, исходные позиции, фильтры и область известных исполнителей сохранены.
- Нормализация имён и названий остаётся общей с JS. Текстовый кэш существует только в синхронной части одного объединения; он не переживает запрос и не удерживается во время сетевых ожиданий.
- До инициализации WASM, для маленькой/слишком большой задачи и при отказе адаптера применяется прежнее JS-сравнение. До переключения хранятся идентификаторы принятых записей и одного рассматриваемого кандидата. После успешного расчёта матрицы временные JS-идентификаторы освобождаются.
- Проверка TypeScript (`npm run lint`) прошла. По текущим инструкциям тесты и бенчмарки не добавлялись и не запускались. Rust и приложение не пересобирались; существующий бинарник ABI 2 совместим с этим подключением. Рабочая установленная сборка получит изменения после следующей сборки приложения.

## Что сначала улучшить на JavaScript

- В удалении дублей переиспользовать готовые идентификаторы и существующее Rust-ядро, а не заводить второй почти одинаковый алгоритм.
- После переноса выбора очереди оценить Worker для больших пакетов. Сам по себе синхронный вызов WASM продолжает занимать вызывающий поток.
- Сетевые ожидания, отмена запросов и восстановление воспроизведения решаются на уровне текущего транспорта. Перенос HTTP-кода на другой язык не исправит недоступный ответ сервиса.
- Агрегация жанров библиотеки уже кэшируется по поколению снимка (`LibraryTasteService.report` и `LibraryTasteStore`). Отчёт `docs/performance-3.1.0.md` описывает отсутствие повторных запросов на тёплом снимке. Переносить кэшированный отчёт на Rust сейчас низкий приоритет.
- Эквалайзер уже использует встроенные Web Audio `BiquadFilterNode`, `GainNode` и `DynamicsCompressorNode`; их DSP выполняется браузером. Подмена этой обработки собственным Rust-модулем потребует новой реализации и отдельного сравнения звучания.
- База уже использует SQLite через sql.js/WASM. Отдельный переход к нативной базе имеет смысл оценивать по большим библиотекам и стоимости сохранения всего файла, а не по языку обвязки.

## Как принимать решение о переносе

Сначала зафиксировать медиану/p95, задержки интерфейса и память на небольших и больших реальных каталогах; отдельно измерить подготовку строк, упаковку, WASM и копирование результата. Для сравнения дублей сохранить русские, латинские и CJK-названия, совместных исполнителей, номера частей, разные длительности и версии песен. Точные условия совпадения важнее самого переноса. Сохранять рабочий JS-резерв и нижний порог размера пакета.

Первые два этапа выполнены: расширено использование Rust-сравнения и перенесён выбор очереди с замерами полного вызова. Точную нормализацию громкости рассматривать отдельной задачей DSP, поскольку она затрагивает звучание.
