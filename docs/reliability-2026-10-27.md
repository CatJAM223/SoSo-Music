# Надёжность воспроизведения и пакетное Rust-сравнение — 27.10.2026

Изменения относятся к исходникам и локально собираемому вычислительному модулю. Пользовательская медиатека и профили аккаунтов не использовались для проверок.

## Исправления

- Обычный progressive-поток получает собственный таймаут старта в 8 секунд. Он работает даже без событий `waiting`/`stalled`, пока `play()` остаётся незавершённым. После подтверждения запуска, замены источника, паузы и демонтажа таймер и слушатели освобождаются. Неожиданный `AbortError` текущего источника сохраняет ограниченный срок ожидания; отменённый владельцем источник не восстанавливается.
- Чтение офлайн-аудио из IndexedDB ограничено 2 секундами. Попадание в RAM по-прежнему обходит дисковое чтение. Таймаут позволяет продолжить поиск онлайн-источника, а отмена немедленно возвращает устаревший результат. Поздний ответ или отказ базы не устанавливает старый источник. Саму начатую транзакцию IndexedDB эта обёртка не отменяет.
- Ошибка `MEDIA_ERR_NETWORK` после исчерпания обновлений ссылки переводит текущий трек в ожидание сети. Сохраняются очередь и позиция; ограниченные автоматические повторы не дают сетевому сбою превращаться в пропуск песни или отрицательный сигнал вкуса.
- Если во время ожидания аудио немного продвинулось, а затем снова перестало получать данные, таймер восстановления запускается повторно. Раньше такое продвижение могло навсегда завершить наблюдение за этим эпизодом буферизации.
- Восстановление источника до завершения начальной перемотки сохраняет запрошенную позицию. Текущее время пустого media element не заменяет её нулём.

## Восстановление запуска

Загрузка и инициализация обязательного Rust-модуля имеют общий срок 15 секунд. При ошибке или превышении срока показываются локализованные кнопки повтора и перезагрузки окна. Кнопка повтора доступна с клавиатуры; параллельные нажатия не создают несколько запусков. Локальные данные не очищаются.

Ошибка инициализации больше не запоминается навсегда внутри `initializeRustCompute`: последующая попытка может загрузить корректный модуль. Одновременные попытки по-прежнему используют один Promise. Устаревший результат запуска после таймаута не монтирует приложение.

Вычислительный модуль остаётся обязательным; резервного алгоритма на JavaScript нет. Экран восстановления позволяет повторить запуск при временной ошибке, а отсутствующий или повреждённый ресурс сборки может потребовать повторной установки полной сборки.

## Локальная диагностика

Новые события `[Playback:Quality]` записываются существующим журналом с прежним удалением секретов и подписанных ссылок:

- `playback-attempt`: запрос запуска, источник и признак автоматической повторной попытки.
- `playback-outcome`: один исход старта — `started`, `failed` или `cancelled`. Повторные `playing` не добавляют успешных стартов.
- `playback-buffering`: длительность эпизода после первого успешного запуска. Первичная загрузка не считается повторной буферизацией; пауза завершает текущий эпизод.
- `playback-interruption`: окончательная приостановка уже начавшегося воспроизведения из-за ошибки.
- `playback-recovery`: начало и исход обновления источника. Успех фиксируется после `playing`, отмена пользователем отделена от ошибки.

Задержки считаются монотонными часами. В библиотеке и при запуске плейлиста из «Моей музыки» учитывается подготовка очереди; её время привязано к реально выбранному объекту трека. Прямой выбор другого трека не наследует время чужого ожидающего чтения.

```powershell
npm run report:playback -- "путь/playback.old.log" "путь/playback.log"
```

Отчёт выводит количество попыток, отмен, отказов, прерываний, восстановлений, эпизодов буферизации и median/p95 успешных стартов по источникам. Названия песен, идентификаторы аккаунтов и ссылки в итог не входят. Пустой отчёт для старых логов означает отсутствие новых событий, а не отсутствие ошибок.

Это показатели отдельных запросов: автоматический повтор образует новый запрос. Конец задержки — DOM-событие `playing`, а не физический звук. Ротация журнала может обрезать начало или конец запроса, поэтому баланс попыток и исходов не следует выдавать за точную доступность сервиса. Сравнение реальных провайдеров потребует данных из новой запущенной сборки.

## Rust: внедрённое ускорение

До изменения недавние принятые песни сравнивались с кандидатом отдельными вызовами Rust. Каждый вызов заново упаковывал метаданные и копировал пакет через границу WASM. Теперь Rust получает до 64 левых записей и одну правую, выполняет цикл и возвращает компактные флаги.

Первые четыре принятые записи проверяются отдельно: частый ранний дубль не требует упаковки остальных. На больших задачах сохраняется существующий переход к плотной матрице. Приём кандидата остаётся отдельной операцией: трек, отклонённый ограничением на исполнителя, не начинает подавлять последующие песни. Независимые потребители не хранят общее изменяемое состояние задачи в Rust.

Сравнение остаётся направленным: принятые записи слева, новый кандидат справа. Старые двухстрочные пакеты сохраняют результат. Контракт модуля обновлён до ABI 5, чтобы старый бинарник не был принят адаптером с пакетными запросами.

### Замер

Windows x64, Node 24.19.0. 31 чередующийся парный прогон после прогрева, по 5 полных удалений дублей в каждом образце. Базовый вариант использует отдельные production Rust-сравнения, новый — production-дедупликатор; WASM-бинарник одинаковый. Время включает проход по принятым записям, упаковку пакета, WASM, копирование и обработку результата. Подготовка неизменившихся текстовых идентификаторов и первоначальная инициализация исключены.

| Синтетический набор              | Попарно, медиана | Пакетно, медиана | Отношение времени |
| -------------------------------- | ---------------: | ---------------: | ----------------: |
| 24 различные записи              |         1,122 мс |         0,636 мс |             1,77× |
| 96 различных записей             |        16,693 мс |         5,993 мс |             2,79× |
| 96 записей, 12 семей перезаливов |         2,253 мс |         1,934 мс |             1,16× |

Порог прежней плотной матрицы на этих размерах не срабатывает. Порядок результатов сверяется перед измерением. Это ускорение конкретного локального участка, не процент ускорения поиска, сети или всего плеера.

Воспроизведение измерения:

```powershell
npm run build:compute
npm run bench:rust-comparisons
```

Сводка последнего запуска сохраняется в `scratch/rust-comparisons-benchmark.json`. Зафиксированные median/p95 этого замера: [JSON](benchmarks/rust-comparisons-2026-10-27.json).
