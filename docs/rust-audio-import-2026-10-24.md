# Rust: офлайн аудио, импорт и громкость — 24.10.2026

Версия приложения: 3.3.0. Изменены исходники и локальные вычислительные ресурсы. Установленная сборка на рабочем столе не заменялась; упаковка приложения не выполнялась.

## Одна реализация вычислений

Обязательное ядро обновлено до ABI 4. Добавлены `demux.rs`, `import_match.rs` и `loudness.rs`. Старый TypeScript демультиплексор, числовой подбор импорта и приблизительный анализатор громкости удалены из production. Резервного JS алгоритма для этих вычислений нет.

TypeScript подготавливает текстовые метаданные, передаёт буферы, управляет сетью и состоянием воспроизведения. Unicode нормализация, извлечение имён и маркеров версий имеют одну общую реализацию на стороне метаданных. Исторический импортный scorer сохранён только в `tests/fixtures/importBeforeRust.ts`; проверка архитектуры запрещает импорт тестов в приложение.

Пакеты общей вычислительной части ограничены 8 МиБ, каждый WASM экземпляр — 64 МиБ. Rust не импортирует возможности хоста и не получает сетевой или файловый доступ. Дополнительных Cargo зависимостей нет.

## Офлайн аудио

Rust разбирает PAT/PMT, выбирает AAC/MP3 PID и извлекает аудио из PES. Видео, метаданные, null packets, адаптационные поля и заголовки PES исключаются. Проверяются CRC таблиц, последовательность аудиопакетов, дубликаты, границы и полнота данных. PSI/PES заголовки и транспортные пакеты могут пересекать границы входных буферов.

Обработка идёт блоками до 1 МиБ по мере загрузки сегментов, с отдельным состоянием для каждого скачивания. Полный объединённый TS буфер больше не создаётся. Поддержаны разрывы HLS, продолжается передача fMP4/CMAF, ADTS и WebM контейнеров. Повреждённый TS не сохраняется через прежний запасной путь с MIME `audio/mpeg`. Зашифрованные HLS и byte-range playlists завершаются явной ошибкой.

Декодирование и перекодирование аудио этим модулем не выполняются. Извлекаемые байты записи сохраняются без изменения.

## Импорт плейлистов

Сопоставление токенов, маскированных названий, исполнителя, версии и длительности, оценка уверенности и стабильное ранжирование выполняются Rust одним вызовом на поисковую выдачу. Сохранены приоритет источника, отмена, тайм-ауты поиска и порядок импортированного плейлиста.

На 1176 комбинациях метаданных получено точное совпадение оценок и уверенности с независимым историческим scorer. Передача оптимизирована: один расширяемый буфер и `TextEncoder.encodeInto`, с подготовкой исходной записи один раз на выдачу. Дополнительные кредиты разбираются при различии основного имени загрузчика.

## Громкость

В отдельном AudioWorklet непрерывно обрабатывается декодированный PCM, приведённый AudioContext к 48 кГц. Rust выполняет K-взвешивание, суммирование каналов, блоки по 400 мс с шагом 100 мс, абсолютный порог −70 LUFS и относительный порог −10 LU. True peak оценивается четырёхфазным FIR из Annex 2.

Основание: [ITU-R BS.1770-5](https://www.itu.int/rec/R-REC-BS.1770-5-202311-I/en). Это реализация алгоритма для mono/stereo; сертификация измерителя по полному официальному набору сигналов не проводилась.

Настройки продукта: цель −14 LUFS, коррекция от −24 до +18 дБ, ограничение усиления по измеренному true peak до −1 dBTP перед эквалайзером. Существующая защита выходного аудиографа сохраняется. Статистики достаточно после трёх секунд пригодного сигнала. Анализ продолжается в доступном потоке; результат обновляется примерно раз в секунду и может представлять прослушанную часть записи.

Усиление остаётся постоянным во время текущего воспроизведения. Новый профиль применяется при следующем запуске записи. Данные провайдера имеют приоритет. Пауза приостанавливает контекст, продолжение использует тот же анализатор; перемотка разрывает неполное окно. Смена трека, отключение функции, отказ процессора и отсутствие отчётов освобождают анализ. Скрытая ветка анализа не подключает исходный звук повторно к выходу.

В renderer передаётся только статистика. PCM ограничен текущим окном и FIR; сохраняются только коррекция и время. Число энергетических блоков ограничено 72000. Профили старого приблизительного измерителя не используются: новая схема хранения `soso_recording_loudness_v2`.

## Измерения

Ryzen 5 3600, Windows x64, Node 24.19.0. Прогретые локальные вызовы; учтены подготовка метаданных, копирование и создание отдельного экземпляра аудиоядра. Начальная компиляция WASM исключена.

| Сценарий                                                            | Результат, медиана |
| ------------------------------------------------------------------- | -----------------: |
| Подбор 24 кандидатов, прежний TS                                    |           0.652 мс |
| Подбор 24 кандидатов, Rust с адаптером                              |           0.592 мс |
| Разбор 12 932 332 байт TS с видео и null packets, выход 4 МиБ аудио |           3.707 мс |
| Анализ 30 секунд stereo PCM, 48 кГц, блоки 128 samples              |         107.380 мс |

Для импорта выполнен 31 чередующийся парный прогон по 100 вызовов; снижение времени локального подбора около 9%. Сетевые задержки в эти числа не входят. Для TS — 31 прогон, для PCM — 15. В замере PCM статистика читается в конце; рабочий AudioWorklet отправляет её примерно раз в секунду. Это измерение вычислений вне реального времени, а не процент загрузки процессора плеером.

Полные выборки: [rust-audio-2026-10-24.json](benchmarks/rust-audio-2026-10-24.json).

## Проверка плеера

Итог: **25 из 25 групп проверок прошли**. Общий Node прогон: **1232/1232**, ошибок и пропусков нет.

- 1232 Node теста: импорт и отмена, работа каталога, воспроизведение, очередь, кэш, ошибки и восстановление.
- Byte-exact TS фикстуры: разные границы от одного байта, перемешанные потоки, частичные заголовки, дубликаты, нарушения CRC/continuity, независимые параллельные задачи и HLS скачивание через IPC.
- DSP: 997 Hz калибровка mono/stereo, амплитуда, пороги тишины, размеры блоков, межсемпловые пики, неполные окна и испорченный PCM.
- Настоящий Chromium: независимость громкости от ползунка и EQ, пауза/продолжение, перемотка, постоянный gain первого воспроизведения, освобождение контекстов, mute/unmute, buffering, равномощный crossfade и защита выходных пиков.
- Сбой процессора, поздние ответы после смены записи, приоритет метаданных провайдера и watchdog не нарушают воспроизведение.
- Общий набор также проверяет старт, IPC, восстановление после сбоев, интерфейс, настройки, фоновые ресурсы, виджет, оверлей, все режимы «Волны» и Worker.

Аудиостенды используют локальные файлы, настоящую CSP и отдельные профили. Живые API сервисов и пользовательская медиатека в этом прогоне не использовались.

## Дополнительно: первый запуск

Исправлен показанный разрыв загрузочной анимации. React fallback занимал `60vh`, а статический экран заменялся другим загрузчиком. Теперь fallback покрывает viewport полностью. Статический экран находится рядом с React root, сохраняет тот же DOM и фазу анимации до коммита lazy приложения и исчезает поверх готового интерфейса. С учётом reduced motion скрывается сразу. Ошибки Rust или Root ErrorBoundary открывают сообщение об ошибке.

Проверены четыре сценария: обычный холодный старт, масштаб 125% со светлой темой, узкое окно с reduced motion и отказ приложения. Проверяются реальные размеры, сохранение элемента кольца, промежуточная прозрачность и удаление загрузчика. Проверка выполняется в offscreen Electron, без видимых окон.
